## Changes Made

### #1313 Harden JSON-schema and regex-based validators against ReDoS

**What existed (on `main`):** 6 direct `regex` crate patterns (auth, GraphQL x2, telemetry, profiling `session_id`, one test-only in `error.rs`) and 3 JSON-schema `pattern` keywords in `callback_schema_v1`, with no inventory and no guard.

**Findings:**
- **No dynamic (operator/tenant-supplied) pattern source exists.** Every direct pattern is a string literal or the `IDENTIFIER_PATTERN` const.
- Direct patterns run on the `regex` crate, which matches in linear time and cannot backtrack catastrophically.
- `jsonschema` 0.17 runs `pattern` on `fancy-regex` 0.11, which can backtrack. But `fancy-regex` delegates any pattern without lookaround or backreferences to the `regex` crate (`RegexImpl::Wrap`), and all three schema patterns qualify. None has a nested unbounded quantifier.
- `cache::validation::validate_pattern` is a Redis glob with hand-written checks, not a regex engine.

**Done:**
- `docs/regex-pattern-audit.md`: engines, a full per-site inventory with static/dynamic classification, and the guard's known limits.
- `src/validation/regex_audit.rs` (`#[cfg(test)]`, 7 tests):
  - `every_regex_constructor_takes_a_static_pattern`: scans `src/` for `Regex::new(` / `RegexBuilder::new(` / `RegexSet::new(` and fails on any argument that is not a literal or a reviewed const.
  - `reviewed_pattern_consts_are_still_used`: prevents a stale allowlist.
  - `schema_patterns_run_on_the_linear_time_engine`: every schema pattern must compile with the `regex` crate.
  - `schema_patterns_have_no_nested_unbounded_quantifiers`, plus positive and negative tests for the detector (`(a+)+`, `(\d+)*`, `(x+){2,}` flagged; `(\.[0-9]+)?`, `(a+){2,5}`, escaped parens and char classes not flagged).
- `callback_schema_v1` / `webhook_schema_v1` changed from private to `pub(crate)` so the guard can walk them.

**Not done in this PR:**
- Creation-time complexity bounds or match-time timeouts for dynamic patterns (AC2). There are no dynamic sources yet; the guard fails CI when one appears.
- proptest fuzzing of adversarial patterns with bounded-time assertions, and the 90% coverage target.

## Changes Made

### #1316 Formally model-check state-machine transition guards

**What existed:** hand-picked example tests for `validate_status_transition` and the transition table. No exploration of event sequences or concurrent writers.

**Done (AC1):** `src/validation/state_machine_model.rs` (`#[cfg(test)]`, 6 tests). The model is derived from `TRANSACTION_TRANSITIONS` and checks the real guard:
- **Exhaustive:** the guard accepts exactly the table's edges plus same-state no-ops, for every pair of known states and a set of non-states.
- **Reachability (BFS from `pending`):** exactly `pending` / `processing` / `completed` / `failed`. `dlq` has an outgoing requeue edge but **no incoming edge**, so rows only enter it through DLQ tooling outside the machine (documented).
- **`completed` is absorbing.**
- **proptest, sequential (512 cases):** arbitrary target sequences, including non-states, never leave the state set or leave `completed`.
- **proptest, interleaved (512 cases):** 3 writers each acting on a stale read. With a compare-and-set write (`UPDATE … WHERE status = <read>`), every persisted change is a valid edge.
- **Counterexample pinned as a regression test:** without the status guard, two writers that both read `pending` can persist `completed -> failed`.

`docs/state-machine.md` gains a "Model Checking" section describing the harness and the counterexample.

**Finding (not fixed here):** `db::queries::bulk_update_transaction_status` uses the unguarded pattern. It `SELECT`s statuses, validates, then runs `UPDATE transactions SET status = $1 … WHERE id = ANY($2)` with no `status` condition, so a concurrent processor write between the read and the update can be overwritten with an invalid transition.

**Mutation checks** (reverted):
- Adding a `completed -> failed` edge to the table fails 3 of the model tests.
- Running the interleaving proptest with the unguarded discipline makes proptest find a counterexample by itself (it shrank to a stale write persisting `failed -> processing`).

**Not done in this PR:**
- Fixing the counterexample in `bulk_update_transaction_status` (AC2 follow-through).
- Settlement and webhook state machines (out of scope per the issue).

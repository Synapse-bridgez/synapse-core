# Swap controls

- **Conditional orders** (`src/swap/order_types.rs`, `triggers.rs`): `limit`, `stop_loss` (fires on a fall), `take_profit` (fires on a rise). A restartable worker reads `status='open'` rows via the `(status, trigger_price)` index and promotes with a conditional `UPDATE ... WHERE status='open'`. Trigger fires at-or-through the price; stale/missing market data fails closed. A triggered order uses the normal market-order path, so slippage protection and min-received apply; if it can't fill within its time-in-force it is `expired`. Only `open` orders can be cancelled/amended.
- **Asset status** (`asset_status.rs`): `ACTIVE | SUSPENDED | FROZEN | DELISTED`; all non-ACTIVE states stop quoting and reject new orders. Delisting is terminal, needs elevated auth, and keeps history. Actions are idempotent and audited in `asset_admin_actions`. In-flight: open quotes/orders are cancelled; executing/filled orders complete (`DrainAndCancelOpen`) or are compensated (`CancelAll`).
- **Best-execution TCA** (`analytics/`): raw inputs are stored in `swap_fill_tca`; metrics derive at query time. Reference price = median of >=2 sources, else the single oracle; a stale snapshot yields null metrics. Unfilled orders are excluded from aggregates.
- **Price quality** (`market_data/quality.rs`): staleness, deviation band vs trailing median, crossed, non-positive, provider disagreement. Anomalies quarantine a provider; it recovers after `recovery_window` clean evaluations. Manual overrides record actor and reason.
